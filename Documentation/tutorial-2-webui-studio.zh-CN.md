# 教程 2：WebUIStudio

WebUIStudio 是随插件提供的桌面工具。它不启动游戏，直接加载工程里真实的网页源码或构建产物，用一个模拟的宿主代替 Unreal，让你逐页、逐状态地查看界面，检查控件，在界面上标注修改意见并交给 Codex 或 Claude。它只用于制作，不进入游戏包。

[English](tutorial-2-webui-studio.md) · [手册目录](README.zh-CN.md) · 相关：[教程 1：用 AI 制作界面](tutorial-1-ai.zh-CN.md)、[教程 4：人工编写界面](tutorial-4-write-by-hand.zh-CN.md)。

本文的界面文字以 1.0.0 的中文界面为准。

## 启动

- **从 Unreal 启动（推荐）**：点击关卡编辑器主工具栏上的 **WebUIStudio** 按钮，它和“添加”“蓝图”等按钮在同一组。Studio 会打开当前工程，并把它标记为已信任。
- **直接启动**：双击插件目录下的 `Binaries/Win64/WebUIStudio.exe`，在弹出的对话框里选择 `.uproject`。这样打开的工程需要手动点一次“信任此工程”。

同一个工程再次启动时，会回到已经打开的窗口。提示 `The plugin's WebUIStudio.exe is missing` 时，说明工具还没有准备好，见[安装](installation.zh-CN.md)。

Studio 的全部数据都在工程的 `Saved/OrionUE/WebUIStudio` 下，包括设置、缓存、标注和报告；第一次启动时，运行文件也展开到这里。它不会往插件目录写配置；在这个目录之外，它只往工程里写一样东西：向 Claude 发送请求时登记在 `.claude/settings.json` 里的 Hook，见[发送](#发送)。

## 信任与运行环境

**信任。** 刚打开的工程只被静态读取：列出界面、读配置，不运行任何工程代码。点击提示条上的“信任此工程”之后，Studio 才会运行预览、安装依赖和发送请求。不要信任来历不明的工程。

**运行环境。** Studio 自带 Node.js 和 npm，这台电脑不需要另外安装它们就能预览。打开工程后它会检查：

| 项目 | 用途 | 缺少时 |
| --- | --- | --- |
| 界面依赖 | 源码预览。指有源码却还没有安装依赖包的界面 | 提示条上点“一键安装环境”，逐个界面按锁文件安装（`npm ci`）；没有锁文件的界面用 `npm install` |
| Codex、Claude 桌面应用 | 接收你发送的标注和新建请求 | 只报告。自行安装并登录 |
| Codex、Claude 命令行与 Git | 生成和验证隔离草稿 | 只报告。其他功能不受影响 |

提示条上的“稍后”把它收起到下次启动。随时可以按 `Ctrl+K`，输入“检查运行环境…”重新检测。

## 认识窗口

| 区域 | 内容 |
| --- | --- |
| 标题栏 | 工程菜单（打开工程…）、命令搜索（`Ctrl+K`）、语言（中 / EN）、外观（跟随系统、浅色、深色）、设置 |
| 左栏 | 界面列表，分“生产界面”和“插件示例”两组；第一行是“新建界面”；可以搜索界面、页面和视图；底部是“场景”“资源与工具”“设置”，发现过程有内容要报告时，它们上方还会出现“发现报告” |
| 上下文条 | “页面”“场景”“分辨率”“来源”四个选择，和“重新加载预览” |
| 舞台 | 按所选分辨率显示真实页面 |
| 工具坞 | “浏览”和四种标注工具，以及标注编号、属性调整预览、截图、预览底色、抓手、缩放 |
| 右栏 | “标注”“检查”“草稿”“日志”四个页签 |

两侧面板可以拖动宽度或折叠。语言、外观、布局、分辨率和上次打开的界面都会记住。

## 打开一个界面

1. 在左栏点一个界面。工程自己的界面在“生产界面”，插件自带的 Showcase 和 Sample 在“插件示例”。
2. 界面有多个页面或视图时，行尾有一个箭头，展开后点某一页或某个视图直接打开它。
3. 在上下文条里选择“来源”：

| 来源 | 读取什么 | 需要 | 特点 |
| --- | --- | --- | --- |
| 源码（实时更新） | App 的 `src` | 界面依赖已安装 | 保存源码后预览立即更新；可以定位到源码行 |
| 构建产物 | App 的 `dist` | 已经构建 | 看到的就是 Unreal 将加载的文件；没有源码定位 |

Studio 发现界面的方式：在工程里找名为 `WebUI` 的目录（任意深度），其中带 `package.json`（含 `orionWebUI`）、`index.html` 或 `dist/index.html` 的子目录就是一个界面。所以放在 `Content` 之外的开发用 App（例如 `Tools/WebUI/UIStyleGuide`）也会被列出。`node_modules`、`dist`、`Saved`、`Intermediate`、`Binaries` 不参与查找。新增或移动界面后点左栏的“重新扫描工程”。

### 分辨率与长宽比

- “分辨率”里有 1920 × 1080、2560 × 1440、3440 × 1440、1280 × 720 和“自定义…”。页面始终按所选的逻辑分辨率排版，窗口大小只影响显示比例。
- 预览右下角外侧有一个拉伸手柄：拖动它改变长宽比，短边保持不变，接近 21:9、16:9、16:10、4:3、1:1 等比例时会吸附。双击恢复 1920 × 1080。

### 缩放、移动与截图

| 操作 | 方式 |
| --- | --- |
| 缩放 | `Ctrl` + 滚轮（以指针为中心），工具坞的放大镜和滑条，`Ctrl+=`、`Ctrl+-` |
| 回到适应窗口 | 点击缩放比例，或 `Ctrl+0` |
| 移动放大后的预览 | 按住鼠标中键拖动，或点工具坞的抓手后用左键拖动 |
| 截图 | 工具坞的“截图并复制”，图片进入剪贴板 |

放大只改变显示比例，页面仍按逻辑分辨率排版。

### 预览底色

游戏界面是画在游戏画面上的，页面大部分是透明的。工具坞的“预览底色”决定透明处显示什么：透明网格（默认）、白色、黑色、灰色、自选颜色，或一张图片。放一张游戏截图作底，可以直接看出文字在真实画面上是否清楚。底色只衬在页面后面，不进入页面；截图会带着同样的底。

## 预览数据从哪里来

Studio 给页面装上了一个模拟的通信接口，所以页面走的是“有宿主”的分支，等着状态事件送来数据。Studio 自己去读 App 提供的预览状态，再通过状态事件发给页面。预览状态按以下顺序查找：

1. `webui-preview.json` 的 `state` 里指明的模块和导出。
2. `src` 下名字同时含有 `preview` 和 `state` 的导出（例如 `createSettingsPanelPreviewState`）。它可以是常量，也可以是没有必填参数的函数。
3. `App.vue` 顶层名为 `state` 的变量，初始值是纯字面量。

三者都没有时，页面打开后停在空状态，左栏的“发现报告”会写明原因。

App 还可以导出自己的预览适配器：一个名字形如 `create…Preview…WebUIApi` 的函数，返回一个自己管理业务状态的通信对象。用“源码”来源时，Studio 把业务数据交给这个适配器，宿主一侧仍由 Studio 负责。App 没有上面三种预览状态时，发现报告把状态来源记为 `adapter`，不再报告空状态。

为了把数据发对，Studio 还要从源码里认出几个名字，所以它们必须写成字面量：

| Studio 要找的 | 源码里的写法 |
| --- | --- |
| 状态事件 | `"ue:<前缀>.state"` 或 `"ue:<前缀>.stateChanged"` |
| 状态回执 | `api.stateCommitted(state.stateRevision)` |
| 就绪事件 | `"<前缀>.ready"` |

模拟宿主的行为与 Unreal 的区别：

- 它会完成显示阶段的握手，页面能正常进入可见状态。
- 输入设备固定为键鼠，除非视图用事件另行指定。
- 页面用 `emit`、`call` 发出的业务操作不会被执行，Studio 以错误码 `studio.unhandledCall` 拒绝。页面必须接住这个拒绝；日志页签会记下每一次。想让按钮在 Studio 里也有反应的页面，可以在接住这个错误码之后改用自己的预览数据模拟，随附的 Showcase 就是这样做的。
- 声音不播放。Native Surface 显示为带名字的占位框。运行时图片和 Unreal 资产显示为占位图。
- 页面访问外部网络会被拦截。

“构建产物”来源不执行源码。预览状态是 `App.vue` 里的字面量时可以直接预览；来自导出的模块时（无论常量还是函数），要先用“源码”来源把这个页面打开一次，Studio 会把它每个视图算出的状态缓存下来，之后“构建产物”才有数据。`src` 下的任何文件或 `webui-preview.json` 变化后缓存失效，需要再打开一次。

## 视图：webui-preview.json

一个页面常常有好几种样子：不同语言、空数据、弹窗打开。在 App 根目录放一份 `webui-preview.json`，把它们登记成视图，就能在左栏逐个打开。它是纯数据，Studio 只读取不执行，也不会进入 `dist`。

各篇教程共用的设置面板可以这样写：

```json
{
	"schemaVersion": 1,
	"views": [
		{ "id": "default", "route": "", "title": "Default" },
		{ "id": "chinese", "route": "", "title": "Chinese", "patch": { "culture": "zh-Hans" } },
		{ "id": "muted", "route": "", "title": "Volume 0", "patch": { "volume": 0 } }
	]
}
```

| 字段 | 含义 |
| --- | --- |
| `schemaVersion` | 固定为 `1` |
| `state.module`、`state.export`、`state.args` | 可选。指明预览状态在 `src/` 下的哪个模块、叫什么名字、调用时传什么参数 |
| `views[].id` | 视图标识，字母、数字、`_`、`-`，App 内唯一 |
| `views[].route` | 所属路由。没有路由的 App 写空字符串 |
| `views[].title` | 列表里显示的名字 |
| `views[].args` | 这个视图调用预览状态时的参数 |
| `views[].patch` | 合并到预览状态上的对象。对象逐层合并，数组和其他值整体替换 |
| `views[].events` | 显示这个视图时由宿主发给页面的事件：`name`、`payload`，可选的时机 `at`（`"afterReady"`、`"afterPresented"`、`"afterStateCommitted"` 或毫秒数） |
| `views[].enter`、`views[].leave` | Intent 名字，用于 InstantScreen 页面。页面用 `requestIntent` 请求其中一个时，预览切到这个视图或回到来时的视图。用 `emit`、`call` 发出的操作不会切换视图 |
| `intents` | 整个界面通用的应答规则，用于 InstantScreen 页面的 `requestIntent` |

- 每个路由的第一个视图是打开页面时的默认视图。
- 只差一两个字段的视图用 `patch`，不必为它给预览状态加参数。
- 随附 Showcase 的 `webui-preview.json` 登记了二十四个视图，其中手柄视图用 `events` 发送输入设备和按键提示，可以作为参考。

不使用 InstantScreen 的 App，建议再放一个只声明“没有额外页面”的 `instant-screen.config.ts`，否则[发现检查](#命令行检查)会报告读不到这个文件：

```ts
export default {
	"screens": []
} as const;
```

## 场景

上下文条的“场景”默认是“动态预览 · 工程源码”：每次打开都按当前源码重新生成。登记了视图的页面每个视图一个这样的场景，名字就是视图的名字。

需要一个源码里没有的特殊状态时，从左栏底部打开“场景”，直接编辑 JSON：初始状态、操作的应答规则、按时间发出的事件。点“校验并保存”后，它成为一个自定义场景，保存在 `Saved/OrionUE/WebUIStudio/scenarios` 下，可以在上下文条里选用。自定义场景是可选的覆盖，不影响动态预览。

场景里定义的“完成”和“拒绝”都是模拟出来的，不代表游戏逻辑真的会这样回答。

## 检查与日志

**检查页签。** 用“控件”工具点一个控件，右栏显示它的控件 Id（没有时显示“未声明”）、所在页面、尺寸、源码文件与行号、组件层级和匹配到的样式规则。“在编辑器中打开”用系统默认程序打开源文件。源码定位只在“源码”来源下可用。

**日志页签。** 按时间倒序记录页面与宿主之间的每一条消息，可以按“全部”“警告”“错误”过滤：

| 方向 | 含义 |
| --- | --- |
| `UE→Web`、`Web→UE` | 宿主发给页面的事件、页面发出的操作 |
| `Result` | 操作的应答。没有模拟的操作在这里显示为错误 |
| `Check` | 版本号等检查，例如回执的版本与发出的不一致 |
| `Console` | 页面的 `console` 输出 |
| `Network` | 被拦截的外部请求 |
| `Vite`、`Host` | 开发服务器与宿主自身的信息 |

页面的未捕获错误、未处理的 Promise 拒绝和 `console.error` 都算错误，被拒绝的操作也算。这时“日志”页签上出现一个红点，面板里显示“错误 N 个”。

**资源与工具。** 左栏底部的“资源与工具”显示当前预览的资源状态（“当前预览的资源”）、这个界面的依赖版本，以及 Studio 自身运行环境的版本。其中的“Editor 资源快照”可以从正在运行的 Editor 导出真实的字体和文字表，它需要 Editor 一侧有一个提供 `ExportRuntimeSnapshot` 工具的本机 MCP 服务；OrionBrowser 插件本身不包含这个服务。没有快照时，预览使用回退字体和占位图，上下文条会标出“字体/资源为回退”。

## 标注并发给 Agent

Studio 可以把“这里要怎么改”连同控件位置、截图和源码行一起交给 Codex 或 Claude，省去用文字描述位置。前提：工程已信任，并且已经安装并登录对应的桌面应用。

### 做标注

在工具坞选择工具，或按 `Ctrl+.` 开关上一次用的标注工具：

| 工具 | 操作 | 记录 |
| --- | --- | --- |
| 控件 | 点击控件；按住拖动则变成框选 | 控件和它的源码位置 |
| 点位 | 在任意位置点一下 | 一个坐标点和所在控件 |
| 框选 | 拖出一个矩形 | 区域和区域内的控件 |
| 圈画 | 按住自由勾画 | 笔迹和范围内的控件 |

选定后弹出标注浮层：

- 写下“想让这里怎么改”，按 `Enter` 保存，`Shift+Enter` 换行，`Esc` 取消。
- 评论为空时，“控件”工具可以用 `↑`、`↓` 改选父级或第一个子控件。
- 对单个控件可以展开“调整属性”，直接改文字、颜色、背景、不透明度、字体、字号、字重、行高、字间距、对齐、内外边距、间隙、宽高、圆角和边框。改动立即在预览里生效，并记成“属性：原值 → 新值”。**这些调整只作用于预览，Studio 不改源码**，它们作为目标值随标注交给 Agent。

保存的标注在页面上显示编号，右栏“标注”页签里可以在页面中定位、修改、换一个目标（“重新选择目标”）、删除和查看截图。一批最多 30 条。页面刷新、源码变化或目标被移除后，标注会标出“需要重新定位”，你必须明确选择新目标。

标注工具启用时，点击不会传给页面；要操作页面先切回“浏览”。

### 发送

1. 在右栏底部写这一批的整体要求。
2. 点“发送给”，选择服务（Codex 或 Claude）和方式：

| 方式 | 在哪里改 | 说明 |
| --- | --- | --- |
| 续用专属聊天 | 直接改当前工程 | 接着上一次由 Studio 发起的聊天；还没有时会新建 |
| 新建专属聊天 | 直接改当前工程 | 在桌面应用里为这个工程新开一个聊天 |
| 已有会话 | 直接改当前工程 | 从列表里挑一个属于这个工程的会话 |
| 隔离草稿 | Studio 保存的一份副本 | 由命令行工具生成候选，你审阅通过后再应用，见[隔离草稿](#隔离草稿) |

3. 需要时调整：模型与推理强度；修改范围（只改样式、允许改共享组件、允许改入口与通信文件）；“计划模式”（这一轮只调研并写出计划，不改文件）。
4. 点“发送标注”。

没有标注时也可以发送：输入框变成“对这个页面的修改要求”，按钮变成“发送整页修改”。这相当于让 Agent 修改当前预览的整个页面，Studio 会附上页面信息和一张截图。整页修改不能用隔离草稿。

发到聊天的请求会自动要求接收方先阅读插件自带的制作 Skill，并写明 Skill 在这台电脑上的位置。

发送之后可以继续工作。右栏的发送记录显示每一条的状态：准备、排队、已提交、处理中、计划待确认、完成、失败等。对方用源码改完之后，预览会通过实时更新直接显示结果。“停止跟踪”只结束 Studio 对这一条的等待，**不会停止桌面应用里已经开始的任务**。

需要知道的两件事：

- 每一批发送的内容冻结保存在 `Saved/OrionUE/WebUIStudio/annotations/batches/<批次>/`：`context.json`、`annotations.md`、`prompt.md` 和截图。之后再改标注，不影响已经发出的内容。
- 每次发给 Claude 时，Studio 都会确认工程的 `.claude/settings.json` 里登记着自己的 Hook，它靠这些 Hook 接收回执。第一次发送和这些条目需要更新时才会写这个文件；写之前的文件备份在 `Saved/OrionUE/WebUIStudio/bridge/backups` 下，其他 Hook 保持不变。`.claude/settings.json` 通常随版本库共享，而这些 Hook 启动的程序在 `Saved` 下；提交前先看一眼这处改动。

## 新建界面

左栏第一行的“新建界面”（命令搜索里也有）打开一个弹窗：

1. 写“界面描述”：要做什么、显示什么、能操作什么。写法见[教程 1](tutorial-1-ai.zh-CN.md#第-3-步用提示词创建界面)。
2. “界面名”可选：大写字母开头，只含字母和数字，用作 AppId，不能与已有界面重名。留空则由接收方命名。
3. 选择发给 Codex 还是 Claude，用新聊天还是专属聊天。
4. 点“发送给…”。或者点“复制提示词”，把完整的提示词粘贴到任意对话里。

Studio 生成的提示词顺序固定：先要求完整阅读制作 Skill 并给出它的位置，然后是你的界面名和描述、工程里已有的界面清单、交付要求。打开“计划模式”时，交付要求换成“只写实施计划，不创建或修改文件”。

对方回报完成后，Studio 重新扫描工程，新界面出现在左栏。Studio 自己不创建任何文件，也不创建 Unreal 资产；需要在 Editor 里完成的步骤由对方在回复里列出。

## 隔离草稿

想先看改动再决定要不要时，用“隔离草稿”：

1. 添加标注，在“发送给”里选 Codex 或 Claude 的“隔离草稿”，点“生成隔离草稿”。
2. Studio 在 `Saved/OrionUE/WebUIStudio/drafts` 下复制一份界面，让命令行工具在副本里修改，然后运行这个界面自己的类型检查、测试和构建。
3. 在“草稿”页签审阅差异，可以把草稿和原工程并排预览。
4. 满意后点“应用到工程”；之后可以“撤销这次应用”。应用和撤销都会先核对文件是否被别人改过，有冲突时不覆盖。
5. 应用后可以点“重建当前界面的 dist”。

限制：

- 所有标注必须属于同一个界面，并且来自“源码”来源。
- 草稿只能修改标注定位到的源码文件，以及你允许时的共享组件、入口与通信文件。它们必须是工程 `Content/UI/WebUI` 下某个 `src` 目录里的 `.vue`、`.ts`、`.js`、`.css`、`.json` 文件。草稿改动了其他任何文件时会被整体拒绝，放在其他位置的界面不能应用草稿。
- 需要对应服务的命令行工具和 Git。

## 命令行检查

同一个程序可以不打开编辑界面做两种检查，适合交给 Agent 或放进脚本。发现检查不开窗口；视图检查会开一个不抢焦点的窗口，结束后自己关闭，检查期间可以照常使用电脑，但不要把它最小化。两者的报告都写在 `Saved/OrionUE/WebUIStudio/checks` 下。

**发现检查**只读文件，不运行工程代码，不要求工程已被信任：

```powershell
$Studio = (Resolve-Path 'Plugins/OrionBrowser/Binaries/Win64/WebUIStudio.exe').Path
$Project = (Resolve-Path 'MyGame.uproject').Path
$Arguments = @('--project', "`"$Project`"", '--check-discovery', '--app', 'SettingsPanel')
$Process = Start-Process -FilePath $Studio -ArgumentList $Arguments -Wait -PassThru
$Process.ExitCode
```

| 退出码 | 含义 |
| --- | --- |
| `0` | 所选界面没有 `error` 级的发现 |
| `3` | 报告里有 `error` |
| `1` | 没能运行 |

程序不向控制台输出，结论只看退出码和 `report.json`。逐项核对：`apps[].pages` 是否列全了页面，每个页面的 `views` 是否列全了视图，`previewState.source` 不是 `none`。`--app all` 检查“生产界面”一组里的全部界面，`--locale zh-CN` 或 `en` 选择报告语言，`--report <目录>` 指定报告位置。

**视图检查**会真的运行页面，逐个视图打开并截图：

```powershell
$Arguments = @('--project', "`"$Project`"", '--check-views', '--app', 'SettingsPanel')
$Process = Start-Process -FilePath $Studio -ArgumentList $Arguments -Wait -PassThru
$Process.ExitCode
```

退出码 `0` 表示每个视图都打开成功并且页面没有报错，否则为 `1`。常用参数：

| 参数 | 作用 |
| --- | --- |
| `--mode dist` | 检查构建产物，默认检查源码 |
| `--click-control <控件 Id>` | 不再逐个视图检查，只做一件事：打开一个视图，用真实的鼠标点击这个控件，等下一行的期望成立。同一个 Id 有多个控件时用 `--click-index <序号>` 选择，从 0 起 |
| `--route <路由>`、`--view <视图 id>` | 配合 `--click-control`：点击前要打开的页面和视图。单独使用时不会缩小检查范围 |
| `--expect-view <视图 id>`、`--expect-state <路径>=<值>` | 点击之后应当切到的视图，或状态里应当出现的值。两者都不给时，等状态出现新的版本号 |
| `--backdrop grid`、`#RRGGBB` 或图片文件 | 这一次检查用的预览底色 |

点击检查只有在预览会应答这次点击时才可能通过：也就是 InstantScreen 页面的 Intent，并且它有应答规则或会切换视图。用 `emit`、`call` 发出的业务操作在 Studio 里会被拒绝，它们的效果无法这样检查。

检查只判断页面渲染出了内容、期望成立，不判断好不好看。截图要打开来看。

## 数据与清理

| `Saved/OrionUE/WebUIStudio` 下的目录 | 内容 |
| --- | --- |
| `settings.json`、`trust.json` | 设置、信任记录 |
| `scenarios`、`seeds` | 自定义场景、预览状态缓存 |
| `annotations`、`creations` | 标注与发送批次、新建界面请求 |
| `drafts`、`jobs` | 隔离草稿与验证记录 |
| `checks` | 命令行检查的报告与截图 |
| `cache`、`screens`、`runtime` | 缓存、截图、展开的运行文件 |

“设置”里的“本地数据”会先列出可以清理的内容，再清理：只包括已关闭预览留下的缓存和超过一天、没有被标注引用的截图。标注、发送记录、草稿和导出不在清理范围内。

`Saved` 通常不进版本库，这些数据不会跟着工程走。要手动删除整个目录，先关闭 Studio；如果向 Claude 发送过请求，工程 `.claude/settings.json` 里那几条 `statusMessage` 为 `Orion WebUI Studio bridge` 的 Hook 指向 `runtime` 目录里的程序，删除前先把它们移除。

## Studio 不能证明什么

Studio 里看到的是网页在模拟宿主下的样子。以下各项必须在 Unreal 里验证：

- 蓝图或 C++ 的逻辑、状态往返和存档
- 真实的键盘、手柄路由和输入法
- 控件音效与业务声音
- Native Surface、运行时图片、Unreal 字体与文字表
- WorldUI 的投影与交互
- 页面透明处与真实关卡叠加后的可读性（预览底色只是近似）
- 性能，以及打包后文件是否齐全

## 排查

| 现象 | 原因与处理 |
| --- | --- |
| 左栏没有我的界面 | 目录不在名为 `WebUI` 的目录下，或者下面三样一样都没有：含 `orionWebUI` 的 `package.json`、`index.html`、`dist/index.html`。补上后点“重新扫描工程” |
| “源码”来源不可选 | 这个界面还没有安装依赖；用“一键安装环境”，或在 App 目录运行 `npm ci` |
| “构建产物”来源不可选 | 没有 `dist/index.html`；运行 `npm run build` |
| 打开后是空状态 | 没有可用的预览状态；看“发现报告”，按[预览数据从哪里来](#预览数据从哪里来)补上 |
| 浏览器里有数据，Studio 里没有 | 预览数据只写在“没有宿主”的分支里；把它导出成预览状态 |
| “构建产物”没有数据 | 预览状态来自导出的模块，还没有与当前源码匹配的缓存；先用“源码”来源打开一次 |
| 点击按钮后日志里出现 `studio.unhandledCall` | 正常：业务操作在 Studio 里不执行。页面应当接住这个拒绝 |
| 发现检查退出码是 3，报告说读不到 `instant-screen.config.ts` | 按[视图](#视图webui-previewjson)一节放一个 `screens` 为空的文件 |
| 不能发送 | 工程未信任，或对应的桌面应用没有安装、没有登录；发往已有会话时，对方必须空闲并且输入框为空 |
| 标注提示需要重新定位 | 页面或源码变了；用“重新选择目标”明确指定 |
